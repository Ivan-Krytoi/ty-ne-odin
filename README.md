# «Ты не один» — сайт поддержки

Сайт номинации **«Медицинские и социальные проекты»** конкурса
**«Добрые Сайты 2026»** (организатор — ВО «ДоброБит»).

**О чём это:** когда человеку тяжело — тревожно, страшно, одиноко —
он не должен разбираться в одиночку. Сайт собирает в одном месте
простые техники психологической самопомощи, памятки первой помощи
и понятные объяснения про донорство крови.

Стек: **React + Supabase (Postgres) + GitHub Pages**.

## Как проверить сайт за 3 минуты

1. **Пройдите разделы** по меню: Главная → Психподдержка →
   Первая помощь → Донорство → FAQ.
2. **Оставьте обращение** в разделе «Психподдержка». Форма примет
   заявку и сохранит её в базу данных — как проверить, см. ниже.
3. **Проверьте две важные мелочи:**
   - красный блок «Нужна срочная помощь?» с номером 112 есть на каждой странице;
   - сузьте окно браузера или откройте сайт с телефона: меню складывается
     в «бургер», блоки перестраиваются, текст читается, при зуме 200%
     горизонтальной прокрутки нет.

## База данных: что это и как проверить за 2 минуты

Сайт хранит обращения и регистрации доноров в **Supabase** — это
облачная база данных (Postgres), то есть «умные» таблицы в интернете.
Данные лежат не на устройстве жюри, а в облаке, поэтому запись,
сделанная из формы на сайте, видна из любого браузера.

Проверка (нужен доступ к проекту Supabase, выдан команде):

1. Открыть dashboard проекта → **Table Editor**: видны таблицы
   `support_requests` (обращения) и `donor_pledges` (регистрации доноров).
2. Отправить обращение через форму на сайте → строка появляется
   в `support_requests`.
3. Счётчик доноров: в **SQL Editor** выполнить
   `select get_donor_count();` — вернёт текущее число.
4. **Приватность по-настоящему, на уровне базы:** обращения прячет
   механизм RLS. Проверка: под ключом `anon` выполнить
   `select * from support_requests;` — вернётся **0 строк**, хотя данные в базе есть.

Если доступ к базе по каким-то причинам недоступен — сайт не падает
и не теряет данные: работает демо-режим (записи сохраняются в
`localStorage` браузера). Но по правилам конкурса проверяют именно
подключённую базу, поэтому основной путь — через Supabase.

## Как развернуть базу с нуля (инструкция по инициализации)

База — **Supabase** (PostgreSQL, облачный бесплатный тариф).

1. Зарегистрироваться на https://supabase.com и создать проект (Free tier).
2. Открыть **SQL Editor** → *New query*, вставить содержимое файла
   `supabase/schema.sql` и выполнить (**Run**). Появятся таблицы,
   ограничения и функция счётчика.
3. Раздел **Project Settings → API**, скопировать два значения:
   - `Project URL` → в `.env` как `VITE_SUPABASE_URL`;
   - `anon public key` → как `VITE_SUPABASE_ANON_KEY`.
4. Создать файл `.env` в корне проекта (шаблон — `.env.example`):

   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhb...
   ```

5. Пересобрать сайт (`npm run build`) и задеплоить. С этого момента
   формы пишут в базу.

## Запустить сайт на своём компьютере

Нужен Node.js 20+.

```bash
npm install
npm run dev        # разработка: http://localhost:5173
npm run build      # продакшен-сборка в dist/
npm run preview    # локальный просмотр сборки
```

## Как сайт попадает на GitHub Pages

1. Создать **public**-репозиторий на GitHub и загрузить код (ветка `main`).
2. Workflow уже добавлен: `.github/workflows/deploy.yml`.
3. В репозитории: **Settings → Pages → Source: GitHub Actions**.
4. После каждого push в `main` сайт пересобирается и обновляется сам.
5. Адрес вида `https://ivan-krytoi.github.io/ty-ne-odin/`.

Ключи базы не попадают в код: в открытом репозитории их хранят как
секреты GitHub:

- **Settings → Secrets and variables → Actions** добавить `VITE_SUPABASE_URL`
  и `VITE_SUPABASE_ANON_KEY`;
- в `deploy.yml` включён блок `env`, который подставляет секреты при сборке.

## Доступность (WCAG 2.1 AA)

- Контраст основного текста 16.9:1, ссылок и кнопок ≥ 4.5:1.
- Вся навигация доступна с клавиатуры: Tab, Enter, Esc (меню),
  видимые focus-обводки.
- Семантическая вёрстка (header/nav/main/section/footer), заголовки
  h1→h2→h3 без пропусков, skip-link к содержимому.
- `prefers-reduced-motion`: анимации отключаются, если пользователь
  просил их убрать.
- Формы: подписи всегда видны, ошибки — текстом с иконкой, `role="alert"`.
